## Configuration and deployment

Edit `.upptimerc.yml` for monitors, branding, and navigation. `assets/theme.css` is
served by GitHub Pages at `/uptime/theme.css`, with a local Inter font under
`assets/fonts/`. The theme follows the system light/dark preference and uses the
neutral palette, orange accent, and narrow typography-led layout from [dhrv.pw](https://dhrv.pw).

All eight Upptime workflows are retained. Uptime CI checks endpoints on
a five-minute cron schedule; GitHub may delay scheduled runs. Setup CI runs when
`.upptimerc.yml` changes and regenerates data, README, graphs, and the status page.
Static Site CI also rebuilds when assets change. Both deployment workflows now
accept push events only on `master` and have a `master` job guard, so pushing this
feature branch or opening its draft PR does not deploy the page.

The branch filters and job guards in `setup.yml` and `site.yml` are local
customizations. Upptime's template updater regenerates these files and can
overwrite the guards. Review regenerated workflow changes and retain these guards
before using future feature branches; Upptime currently has no config option for
preserving custom branch filters. The other six workflows are unchanged and
have no push or pull-request triggers.

To activate these changes after merging into `master`:

1. Let **Setup CI** complete, then run **Uptime CI** and **Summary CI** to refresh
   the initial status and response-time data. Run **Static Site CI** if the page
   needs rebuilding after those checks.
2. Verify GitHub Pages is configured to publish from the `gh-pages` branch, root
   directory. The existing public URL is <https://0xdhrv.github.io/uptime/>; no
   custom domain or DNS change is needed.
3. Remove the `status` label from [the retired Week Flow incident #135](https://github.com/0xdhrv/uptime/issues/135)
   and close it as **not planned**. Upptime does not automatically resolve an
   incident for an endpoint removed from the configuration. Removing that label
   keeps this retirement out of both the active incidents and recovery feed;
   the issue and historical logs remain available in GitHub.
4. Check each new monitor and an individual history page, both theme modes, and
   the mobile layout after deployment.

The existing Actions runs already succeed. These public HTTP checks need no
service API keys. Keep the repository's working token configuration; no new
credentials, account permissions, or notification integrations are required for
this change. Optional notifications can be configured separately using the
[Upptime notification docs](https://upptime.js.org/docs/notifications/).
